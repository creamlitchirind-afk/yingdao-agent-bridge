# 三周考勤汇总：完整业务样例

本例展示 AI 如何通过影刀调用可检查的 Excel 处理程序，而不是训练好的模型或通用任意表格解析器。影刀代码流程调用本仓库 Python；业务汇总使用 openpyxl，不要求安装 Microsoft Excel。Kunar 可以按本页指导完成安装、创建、运行和核对。

## 材料

`examples/attendance/data` 含78个Excel：两份空白总表/周模板、13个学院×3周的39份课堂考勤表、37份晚点名表。姓名为模拟数据；学院、班级、学校及邮箱已替换为演示内容。不包含原始学生名单、真实学号、姓名映射、本机账号或运行日志。数据格式来自本项目考勤案例，供演示与测试使用。

普通考勤表仅列违纪学生，每份4—10人；全勤不列学生。缺勤×按每格1学时；迟到○与早退#分别在课程首尾，同堂合计0.5学时；请假△/R不计学时。`课时分组.json` 明确上午1—3、4—5，下午6—8，晚上11—13的课程边界，**仅适用本例**，换真实课表时必须更新，不应猜测边界。

晚点名每次未签到计3学时，人数须与名单一致。全勤要求两份材料都收到且均无违纪；无违纪但材料不齐，合并B:E红字“未及时报送”，排最后（累计表B:F）。有课堂违纪但缺晚点名时保留名单，备注“未报送，该名单为学工处考勤结果”。学院排序为全勤、异常学生人数升序、未报送；同学院学时降序、姓名升序。累计全勤要求每个已汇总周材料都齐全。累计缺晚点名提示按学院各周缺报情况合并，不表示每个学生都来自缺报的那一周；要查看具体来源请看周页与本地台账。

## 先验证材料处理

按README安装依赖后，在仓库目录执行：

```powershell
.\.venv\Scripts\python.exe examples\attendance\run_demo.py
```

默认写入 `.local/attendance-output`，不会覆盖输入文件。打开第1-3周总表，查看累计页及第一周、第二周、第三周。需要关闭已打开的输出Excel后再重跑，否则Windows可能拒绝覆盖。

| 范围 | 异常学生人数 | 学时 |
| --- | ---: | ---: |
| 第一周 | 80 | 162 |
| 第二周 | 94 | 176.5 |
| 第三周 | 89 | 145 |
| 累计去重 | 124 | 483.5 |

第三周学院丙缺晚点名且考勤无异常，应在最后合并显示未及时报送。具体学院代称以测试和材料内容为准。重复导入替换对应周台账，再计算累计，不追加重复数据。

## 在影刀中运行

先按README完成doctor和绑定，使用已保存的专用测试应用：

```powershell
.\.venv\Scripts\python.exe tools\install_attendance_example.py --write
.\.venv\Scripts\python.exe scripts\yingdao.py run --flow-id "刚返回的flow_id" --write
```

安装器只创建一个新的独立代码流程并保存，不改主流程、不自动运行。新流程依次处理三周。必须在当前虚拟环境安装依赖，仓库移动后重新生成流程入口。代码流程接口是否可用取决于本机影刀版本和账号权限。

## 可在Kunar中使用的示例描述

> 使用yingdao-agent-bridge技能。阅读仓库docs/ATTENDANCE.md及这套样例，检查影刀连接和绑定。在专用测试应用中新建三周考勤汇总流程；不要修改已有流程。按两份材料齐全才全勤、缺报放最后、同堂迟到早退计0.5的规则运行，并核对每周人数、学时、第三周缺报学院的位置和合并样式。

当前能力是这套固定格式的可复现业务样例。不同列结构、日期规则、学院数量（目前固定13）、不同学期（目前样例为2025-2026第一学期）需要适配代码和测试；不要把它描述为已经支持任意学校的考勤表。
