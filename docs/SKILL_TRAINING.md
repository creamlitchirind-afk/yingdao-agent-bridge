# Skill经验的来源与培养方法

这里的“训练”是把查证资料、真实接口、任务配方、失败修复和验收程序整理成可复用Skill，没有微调或分发模型权重。用户描述当前需求，助手选择实际可用工具；本地脚本协调开发接口，影刀执行操作，独立程序核对结果。一次完整用户需求可以包含多次推理及工具调用。

## 资料来源

- [官方CLI Skill](https://github.com/ying-dao/skills/blob/main/shadowbot-cli/SKILL.md)：先查真实帮助、命令发现及生命周期方法。
- [官方MCP Server](https://github.com/ying-dao/yingdao_mcp_server)：既有应用运行能力与Studio开发能力的边界。
- [社区yingdao-xbot-ai-agent](https://github.com/apexcheng/yingdao-xbot-ai-agent)：xbot-tools、代码项目与保存同步诊断经验。
- 本机tools/list、实际指令目录、流程回读及运行日志：当前参数与能力的直接依据。
- 本项目四列筛选、完整考勤、PDF/表格及真实练习商城案例：失败修复、配方与结果核对方法。

上游快照和许可说明见[THIRD_PARTY.md](../THIRD_PARTY.md)。没有复制上游Skill全文、影刀知识库或产品内置资料到发布包。文档存在不等于能力已经实测。

## 固化的经验

| 实际问题 | 形成的方法 |
|---|---|
| MCP可连但needs_workspace | 核对账号、应用、版本与编辑器上下文，不能只看端口或工具数量 |
| 把工具名当RPC方法 | 区分tools/list与tools/call；具体工具名放在调用参数 |
| 旧schema与现场不一致 | 查帮助、schema、指令目录和回读，不编造参数或输出槽 |
| 填了参数但输出错误 | 回读fields.value，填写inputs/outputs语义值，核对变量、坐标及模式 |
| 条件循环曾被误判不支持 | 以实际forin/if/endloop及输出纠正，调用失败不能直接证明产品不支持 |
| 仅最后一条输出 | 区分坐标与递增赋值；当前筛选用列表收集后批量写入 |
| 日期/空值包装导致误判 | 只做有依据的类型和常量归一化，仍精确核对时间、类型及每行 |
| 登录有文字但表单未收到 | 模拟输入并回读，触发真实控件事件，保留失败运行 |
| 翻页却重复采旧页 | 等页码、首订单变化、商品匹配；保存每页及末页证据 |
| CMD/PowerShell混用 | 固定环境启动器，status自带等待；按实际解释器转义参数 |
| 已打开同名报表阻止保存 | 文件名含时间及短标识，不擅自关闭用户旧文档 |
| WPS COM重复运行不稳定 | 原生文件、窗口、剪贴板与键盘前台写入，如实说明实现 |
| 冻结首行使Ctrl+Home落A2 | 空白资产不冻结；表头必须在A1:E1，不能只看总量 |
| 运行成功但业务不正确 | 核对每人/每行、顺序、类型、源哈希及实际格式边界 |
| 模型删除状态来继续任务 | failed/pending/不确定时保留同一任务，不掩盖失败 |
| 额外清理脚本触发审批 | 核验通过就汇报，不额外写核验脚本或清理文件 |

## 案例关系和边界

四列筛选是17条原生指令的固定结构。完整学院汇总另含课表、晚点名、身份归并、缺报、排序、模板和版本事务；仓库提供完整代码引擎与按周入口，现场部分图形化记录单独说明，不能称为仓库已交付纯图形全业务版。

商城终版165条原生指令验证了查询、条件等待、关联行提取、循环筛选、末页停止、数值金额、可见填表、保存后保持打开；不是任意网页一次成功。空白xlsx没有业务值，订单来自本次页面。

## 验证层级

1. 资料与计划预检：参数名/结构可用，尚未证明运行。
2. 实际回读：修改确实落到指定应用及流程。
3. 真实run_id及终态：不把超时、不确定或其他流程错误改为成功。
4. 文件业务核验：源文件保持、全部记录与顺序、筛选去重、金额/日期及本例格式要求。
5. 新任务复用：改变商品/页数/输入；Kunar在一次完整需求下选择入口并完成。

维护者开发、Kunar任务、桌面录屏分别记录。原始日志和机器/账号配置保留本地，仓库发布公开摘要与可重现测试；不把模拟预期当真实结果，也不把一次成功扩展成任意任务可靠。
